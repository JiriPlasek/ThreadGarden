# @threadgarden/service

Long-lived Node service that owns Claude Code and Codex sessions and serves the UI over a token-authenticated WebSocket bound to `127.0.0.1` (random port).

Codex support:

- Install the Codex CLI and sign in with `codex login`. Choose one of its models in New chat's model picker. Models use their native display names; the internal `codex:` routing prefix is hidden. Models and reasoning levels come from the installed CLI's `model/list` catalog, including before any chat runs. `THREADGARDEN_CODEX_PATH` overrides executable discovery; native binaries and npm's Windows launchers are supported. Claude's executable and Anthropic key are not required for Codex chats.
- `src/sdk/multi-adapter.ts` routes qualified model values (`codex:<model>`) and session ids (`codex-<uuid>`). `codex-client.ts` speaks newline-delimited JSON RPC to a local `codex app-server`; `codex-adapter.ts` translates events into the existing normalizer contract. The UI, lifecycle, permission cards, replay, search, and history index remain shared.
- Codex owns the model context. The service stores a thread mapping and a display journal under `<data dir>/codex/`, so ending, idle reclaim, or restarting the service can resume the same thread. Copy resume command uses the real Codex thread id. History discovery imports root conversations from the configured `CODEX_HOME`, including archived CLI/editor/app-server sessions, excluding ephemeral and child-agent threads. It reads native history without resuming it, handles legacy and paginated history, and polls changes every 30 seconds independently of Claude's watcher. Settings can override the Codex executable and data folder; each saved chat remembers its original home for resume.
- Codex's Default mode uses a read-only sandbox and on-request approvals. Accept edits uses workspace-write and on-request approvals. Don't ask permissions uses `approvalPolicy: never` plus `danger-full-access`, equivalent to CLI YOLO. Claude's explicit Bypass permissions selection uses its `bypassPermissions` mode. Agent-suggested rules cannot turn on full access.
- Plan uses Codex's native planning collaboration mode with a read-only sandbox; Implement plan explicitly switches to accepting edits. Auto uses Codex's native `auto_review` approval reviewer with workspace-write. Imported chats keep their native sandbox/approval policies until the user chooses a mode. Custom policies are shown as custom rather than silently replaced.
- A conversation keeps its runtime; start a new chat to switch between Claude and Codex. Shared controls cover text/images, streaming, reasoning summaries, tool results, permission/questions, interrupts, queued turns, reasoning controls, and owned background terminal/agent activity and stop controls. Native context readings and ChatGPT subscription windows are shown separately from Claude's; scheduled sends use the chat's own provider's limits. Costs are omitted when not reported. Imported history may lack token/context telemetry: the app does not invent those measurements. Chat cards show small provider marks only when the displayed list contains both providers.
- Live external detection uses Codex's existing shared daemon. Independent standalone CLI app-servers are outside that daemon's loaded-thread list. Unavailable detection and uncertain resume safety are reported explicitly; an accessible daemon with no matching thread still cannot rule out standalone processes. Threadgarden never stops or restarts the user's daemon. On Windows, shared-runtime access can be denied by the local socket permissions even when history import works.
- Codex fork, cross-machine move, automatic small-model title generation, and CLI slash commands are currently unavailable. Fork/move controls are hidden and backend operations reject unsupported transfers. Native titles or first prompts name Codex chats; Threadgarden renames remain local. Claude-only title generation is labeled in Settings. The shared host controls `/model`, `/effort`, and `/permissions` remain available.
- Integration reference: [Codex app-server](https://learn.chatgpt.com/docs/app-server). Opt-in live checks: `pnpm --filter @threadgarden/service exec vitest run --config vitest.real.config.ts test/real/codex.real.test.ts`. Set `THREADGARDEN_TEST_CODEX_INFERENCE=1` to also run a real two-turn inference/resume check using the CLI's login.

Real Codex verification:

- Set `THREADGARDEN_TEST_CODEX_INFERENCE=1` and `THREADGARDEN_TEST_CODEX_SANDBOX=1`, then run `pnpm --filter @threadgarden/service exec vitest run --config vitest.real.config.ts test/real/codex.real.test.ts test/real/codex-workflows.real.test.ts test/real/codex-sandbox.real.test.ts`. All 15 live checks passed on Windows with CLI 0.167.0: model/effort changes, images, streaming/resume/context/usage, approvals/denials, YOLO, Plan, automatic review, sandboxed edits and Node tests, background work, queues, and interruption. Every Codex connection is real; the unused Claude adapter is a fake.
- Fixtures use disposable directories. Tests verify approved writes, absence of denied writes, ordinary sandboxed commands, and in-workspace Plan implementation. Separate cases deliberately request escalation for their own harmless outside-workspace fixtures. Failed runs save test-only diagnostics under ignored `dist/codex-real-failures/`.
- Windows toolchain permissions matter independently of Threadgarden. NVM installations inside a private user profile can deny the dedicated `CodexSandboxUsers` accounts access to Node. The standalone CLI reproduces this as Windows error 5. Validation required an explicitly approved read/execute grant to the current Node version folder; the original ACL is backed up under ignored `dist/permission-backups/`. The app does not modify system permissions or automatically switch to full access.

- Data dir: `%APPDATA%\threadgarden`, `~/Library/Application Support/threadgarden` or `${XDG_DATA_HOME:-~/.local/share}/threadgarden` (override with `THREADGARDEN_DATA_DIR`; the old `PAHUB_DATA_DIR` still works for one release, with a deprecation note). `src/migrate-data-dir.ts` copies pahub's `pahub.db` from the old `pahub` dir (or inside the override dir) to `threadgarden.db` once, before the service takes its lock, with `VACUUM INTO` a temporary file that is renamed when complete; the start fails while a pahub service still holds the old dir's lock (v1.3 §9).
- `service.json` (mode 0600) advertises pid, port, token and versions; `service.lock` enforces a single instance.
- The service exits after 30 minutes with no live sessions, no clients and no pending scheduled sends.
- Claude Code is driven only through `src/sdk/adapter.ts` (`AgentAdapter`, pinned `@anthropic-ai/claude-agent-sdk`); tests use `src/testing/fake-adapter.ts`. `src/chat/normalize.ts` maps every SDK message to a protocol `ChatItem`, with unrecognised messages and content blocks becoming `unknown` items that carry the raw JSON.
- `src/chat/live-session.ts` runs one live chat (send/queue, permission, question and plan flow, status, header) and emits sequenced `chat.items` / `chat.status` events, coalesced to at most one items event per 33 ms, into a per-session `EventLog` (last 5,000 events) for gap-free reconnect replay. `src/chat/session-host.ts` manages lifecycle: resume on demand, End session, Stop all work, idle reclaim (pinned and waiting chats are never reclaimed) and marking sessions that were live when the service stopped as interrupted.

- `src/sdk/real-adapter.ts` is the real `AgentAdapter`: one streaming-input `query()` per session, with the options Threadgarden always uses (user/project/local settings, `claude_code` system prompt preset, partial messages, the installed `claude`). `src/sdk/claude-path.ts` finds that `claude` (settings path, `PATH`, `~/.local/bin`, `~/.claude/local`; no bundled-binary fallback). `src/sdk/startup-failure.ts` explains each reason Claude Code gives for refusing to start.

- `src/main.ts` wires it all: the entry finds `claude` (again whenever the Claude path setting changes), builds the provider adapter and a `SessionHost` backed by `threadgarden.db`, recovers interrupted chats, and serves every protocol method. Without `claude` the service still starts: history and Codex work; Claude creation/resume fail with `CLAUDE_MISSING`. `system.status` reports each installed runtime. `src/server/handlers/chat.ts` holds the `chat.*` methods. `chat.open` merges adapter history with the live session's items. Permission modes are validated per runtime, with full access available only through an explicit user selection. Sending to a non-live chat re-checks resume safety (`RESUME_BLOCKED`); Codex reports that concurrent terminal use cannot be verified. `chat.since` answers `GAP` when the client must reload. Each service start numbers chat events in a new epoch, so a seq from a previous process is always a `GAP`. `auth.setApiKey` keeps the Anthropic key in memory only.
- `src/usage/` (v1.3): `usage.ts` folds the sessions' `rate_limit_event`s into the account's latest state per window (persisted in `threadgarden.db`, `usage_limits`), remembers the chats a limit refused, and reads the SDK's experimental usage answer on demand (feature-detected, at most once a minute, lenient, falling back silently); `scheduled.ts` stores scheduled sends (`scheduled_sends`) and sends them through `chat.send` at their time, one per turn per chat, waiting for a known limit reset and moving to the new reset once if still refused. `src/server/handlers/usage.ts` holds `usage.get` and `scheduled.*`. Pending scheduled sends keep the service from exiting on idle.
- Analytics (v1.3): `src/history/stats.ts` extracts per-session statistics (messages and tokens per local day and model, tool calls, subagent types, messages per hour) during the indexer's `getSessionMessages` walk; `Db.replaceStats` stores them in the `stats_*` tables and keeps the all-sessions `stats_all_*` sums; `Indexer.backfillStats` gathers them for sessions indexed before, in the background; `src/history/analytics.ts` answers `analytics.get`.
- Threadgarden never writes under the Claude config dir: `test/e2e/read-only.test.ts` runs a full lifecycle against a fixture `CLAUDE_CONFIG_DIR` and compares sizes, mtimes and hashes before and after.

Scripts: `pnpm --filter @threadgarden/service dev` (tsx, `src/bin.ts`), `build` (esbuild bundles `src/bin.ts` with every dependency, the Agent SDK included, into one ESM file `dist/service.mjs` that plain `node --disable-warning=ExperimentalWarning dist/service.mjs` runs; release builds ship it next to the Node sidecar), `mock`, `test`, `test:perf` and `test:real`. `src/main.ts` only exports `startService`; the executable entry is `src/bin.ts`, so bundles and tests that import `startService` never start the real service. `test:perf` runs the §8 budget tests (`test/perf/*.perf.test.ts`, including the idle RSS of the bundled service after indexing 1,000 sessions) one file at a time, after `test`, with budgets multiplied by `THREADGARDEN_PERF_SLACK` (default 1; CI uses 3). `mock` starts the real service in temp dirs over a synthetic history (1,000 sessions, 50 projects, one 2,000-message session, dated over the last 150 days with models, token usage and tool calls for the Analytics view) with a scripted fake Claude Code. Replies stream; a message containing "perm", "ask" or "plan" raises a permission request, a question or a plan approval, and "limit" refuses turns for two minutes as a reached usage limit would (the mock account also reports usage, so the meter shows). It prints its discovery record (port, token) as one JSON line on stdout. `THREADGARDEN_MOCK_PORT` / `THREADGARDEN_MOCK_TOKEN` (or `--port` / `--token`) fix the port and token. `test:real` runs `test/real/**` (one file at a time) against your installed `claude` and its login, so it is opt-in and never runs in `test` or CI. `smoke.real.test.ts` checks a single turn, startup failures and which authentication a session picks. `service.real.test.ts` runs the whole service over the WebSocket against your real history, in a throwaway git repo with a temp data dir: indexing, a Bash permission round trip (`echo` into the repo), user-message uuids in the transcript, resume after `chat.end`, an `@file` mention, fork, `/compact`, and opening and annotating an old chat. It snapshots (size, mtime, SHA-256) every file under the real `<config>/projects/` and `settings.json` before and after, and fails on any change except growth of transcripts that other running Claude Code sessions were already writing (`test/real/claude-snapshot.ts`); the temp repo's own transcripts are left in place. Findings are in `docs/architecture.md`.
