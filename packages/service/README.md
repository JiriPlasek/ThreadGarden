# @pahub/service

Long-lived Node service that owns Claude Code sessions and serves the UI over a token-authenticated WebSocket bound to `127.0.0.1` (random port).

- Data dir: `%APPDATA%\pahub`, `~/Library/Application Support/pahub` or `${XDG_DATA_HOME:-~/.local/share}/pahub` (override with `PAHUB_DATA_DIR`).
- `service.json` (mode 0600) advertises pid, port, token and versions; `service.lock` enforces a single instance.
- The service exits after 30 minutes with no live sessions and no clients.
- Claude Code is driven only through `src/sdk/adapter.ts` (`AgentAdapter`, pinned `@anthropic-ai/claude-agent-sdk`); tests use `src/testing/fake-adapter.ts`. `src/chat/normalize.ts` maps every SDK message to a protocol `ChatItem`, with unrecognised messages and content blocks becoming `unknown` items that carry the raw JSON.
- `src/chat/live-session.ts` runs one live chat (send/queue, permission, question and plan flow, status, header) and emits sequenced `chat.items` / `chat.status` events, coalesced to at most one items event per 33 ms, into a per-session `EventLog` (last 5,000 events) for gap-free reconnect replay. `src/chat/session-host.ts` manages lifecycle: resume on demand, End session, Stop all work, idle reclaim (pinned and waiting chats are never reclaimed) and marking sessions that were live when the service stopped as interrupted.

- `src/sdk/real-adapter.ts` is the real `AgentAdapter`: one streaming-input `query()` per session, with the options pahub always uses (user/project/local settings, `claude_code` system prompt preset, partial messages, the installed `claude`). `src/sdk/claude-path.ts` finds that `claude` (settings path, `PATH`, `~/.local/bin`, `~/.claude/local`; no bundled-binary fallback). `src/sdk/startup-failure.ts` explains each reason Claude Code gives for refusing to start.

- `src/main.ts` wires it all: the entry finds `claude` (again whenever the Claude path setting changes), builds the `RealAdapter` and a `SessionHost` backed by `pahub.db`, recovers interrupted chats, and serves every protocol method. Without `claude` the service still starts: history works, `system.status` reports the problem and `chat.create` / resuming fail with `CLAUDE_MISSING`. `src/server/handlers/chat.ts` holds the `chat.*` methods. `chat.open` merges SDK history (`getSessionMessages`) with the live session's items. Permission modes are limited to default/acceptEdits/plan/auto (no bypass, including "always allow" suggestions). Sending to a non-live chat re-checks resume safety (`RESUME_BLOCKED`). `chat.since` answers `GAP` when the client must reload. Each service start numbers chat events in a new epoch, so a seq from a previous process is always a `GAP`. `auth.setApiKey` keeps the key in memory only.
- pahub never writes under the Claude config dir: `test/e2e/read-only.test.ts` runs a full lifecycle against a fixture `CLAUDE_CONFIG_DIR` and compares sizes, mtimes and hashes before and after.

Scripts: `pnpm --filter @pahub/service dev` (tsx), `build` (bundles `dist/service.mjs`), `mock`, `test`, and `test:real`. `mock` starts the real service in temp dirs over a synthetic history (1,000 sessions, 50 projects, one 2,000-message session) with a scripted fake Claude Code. Replies stream; a message containing "perm", "ask" or "plan" raises a permission request, a question or a plan approval. It prints its discovery record (port, token) as one JSON line on stdout. `PAHUB_MOCK_PORT` / `PAHUB_MOCK_TOKEN` (or `--port` / `--token`) fix the port and token. `test:real` runs `test/real/**` against your installed `claude` and its login. It sends one tiny prompt, so it is opt-in and never runs in `test` or CI. Authentication findings are in `docs/architecture.md`.
