# desktop

pahub's desktop app: a Tauri 2 shell (Rust, `src-tauri/`) around a SvelteKit 3 static SPA (`src/`, Svelte 5 runes, Tailwind CSS 4, shadcn-svelte theme tokens for light and dark). The UI talks to the service directly over its WebSocket; Rust handles only native concerns.

- **Service launch** (`src-tauri/src/service.rs`, `discovery.rs`): `service_connection` reads `service.json` from pahub's data dir (same rules as the service, passed to it as `PAHUB_DATA_DIR`), checks the pid is alive and that `hello` answers, and otherwise starts the service **detached** (Windows: `DETACHED_PROCESS | CREATE_NEW_PROCESS_GROUP | CREATE_NO_WINDOW`, breaking away from the app's job object when allowed; Unix: a new session via `setsid`; stdio to the null device) and waits up to 5 s for a fresh `service.json`. An incompatible protocol gives `service-version-mismatch`; with a compatible protocol the result also carries `serviceVersion` and `appVersion`, so the UI can offer "Restart the pahub service to update" when they differ. Debug builds run the system `node` on `packages/service/dist/service.mjs`; release builds run the bundled `pahub-node` sidecar on the `service/service.mjs` resource. Both pass `--disable-warning=ExperimentalWarning` (`node:sqlite`).
- **Window and tray** (`tray.rs`): closing the window hides it; the tray offers "Open pahub", "Stop all work…", "Quit pahub (keep agents running)" and "Quit pahub completely…". The two "…" items emit `tray://stop-all` / `tray://quit-all` to the UI, which confirms and calls the service. `set_tray_needs_you` sets the tooltip (and the tray title on macOS/Linux). A second launch focuses the existing window (single-instance plugin).
- **API key** (`secrets.rs`): `api_key_get` / `api_key_set` / `api_key_clear` use the OS credential store through the `keyring` crate (v4, default `v1` feature: Windows Credential Manager, macOS Keychain, and the Linux Secret Service over D-Bus via pure-Rust zbus, so no `libsecret` is needed). Entry: service `pahub`, user `anthropic-api-key`.
- **`src/lib/native.ts`** wraps every command and plugin (notification, dialog, clipboard, autostart). Outside Tauri it falls back to stubs and connects to the mock service given by `VITE_PAHUB_MOCK_URL` (e.g. `ws://127.0.0.1:7357`) and `VITE_PAHUB_MOCK_TOKEN`.

Scripts: `pnpm --filter desktop tauri dev` (builds the service first, then opens the app on the Vite dev server), `build` (static UI into `build/`), `test` (Vitest), `typecheck`, `lint`. Rust: `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings` and `cargo test` in `src-tauri` (the UI must be built first). UI against the mock service: `PAHUB_MOCK_PORT=7357 PAHUB_MOCK_TOKEN=dev pnpm --filter @pahub/service mock`, then `VITE_PAHUB_MOCK_URL=ws://127.0.0.1:7357 VITE_PAHUB_MOCK_TOKEN=dev pnpm --filter desktop dev`.

Release bundles add `src-tauri/tauri.bundle.conf.json` (`tauri build --config src-tauri/tauri.bundle.conf.json`), which bundles the service and the Node sidecar; the sidecar binary is fetched into `src-tauri/binaries/` by the release tooling. Icons in `src-tauri/icons/` are generated from `app-icon.png` with `pnpm --filter desktop tauri icon app-icon.png`.
