# desktop

Threadgarden's desktop app: a Tauri 2 shell (Rust, `src-tauri/`) around a SvelteKit 3 static SPA (`src/`, Svelte 5 runes, Tailwind CSS 4, shadcn-svelte theme tokens for light and dark). The UI talks to the service directly over its WebSocket; Rust handles only native concerns.

- **Service launch** (`src-tauri/src/service.rs`, `discovery.rs`): `service_connection` reads `service.json` from Threadgarden's data dir, then from pahub's old one (v1.3 §9: a pahub service still running there reports its older protocol, and restarting it lets the new service migrate; `service_stop` stops a service recorded in either), with the same rules as the service (both dirs are passed to it as `THREADGARDEN_DATA_DIR` and `THREADGARDEN_LEGACY_DATA_DIR`; the old `PAHUB_DATA_DIR` override still works, with a deprecation note), checks the pid is alive and that `hello` answers (offering the token as both `threadgarden.<token>` and `pahub.<token>`), and otherwise starts the service **detached** (Windows: `DETACHED_PROCESS | CREATE_NEW_PROCESS_GROUP | CREATE_NO_WINDOW`, breaking away from the app's job object when allowed; Unix: a new session via `setsid`; stdio to the null device) and waits up to 15 s for a fresh `service.json`. An incompatible protocol gives `service-version-mismatch`; with a compatible protocol the result also carries `serviceVersion` and `appVersion`, so the UI can offer "Restart the Threadgarden service to update" when they differ. Debug builds run the system `node` on `packages/service/dist/service.mjs`; release builds run the bundled `threadgarden-node` sidecar on the `service/service.mjs` resource. Both pass `--disable-warning=ExperimentalWarning` (`node:sqlite`).
- **Window and tray** (`tray.rs`): closing the window hides it; the tray offers "Open Threadgarden", "Stop all work…", "Quit Threadgarden (keep agents running)" and "Quit Threadgarden completely…". The two "…" items emit `tray://stop-all` / `tray://quit-all` to the UI, which confirms and calls the service. `set_tray_needs_you` sets the tooltip (and the tray title on macOS/Linux). A second launch focuses the existing window (single-instance plugin).
- **API key** (`secrets.rs`): `api_key_get` / `api_key_set` / `api_key_clear` use the OS credential store through the `keyring` crate (v4, default `v1` feature: Windows Credential Manager, macOS Keychain, and the Linux Secret Service over D-Bus via pure-Rust zbus, so no `libsecret` is needed). Entry: service `threadgarden`, user `anthropic-api-key`. A key found only under the pre-v1.3 service name `pahub` is moved to the new entry when read; saving or removing the key also removes the old entry.
- **Main layout** (`src/lib/components/layout/`): `AppShell` arranges places (`PlacesColumn`: smart folders with counts, among them the buckets Active, On hold and Archived, then pinned and recent projects), the chat list (`ChatList`/`ChatListRow` on a `VirtualList` with fixed row heights per kind of row and sticky section headers; recency sections from `sections.ts`; search and paging through `sessions.list`; multi-select with a bulk bar, and E/H/A to archive, hold or make active), the open chat with `TabsBar`, and the running-agents `AgentsStrip` ("Stop all work" behind the reusable `ConfirmDialog`). The first two columns resize (drag or arrow keys on the separator; widths debounced into `uiState`) and collapse. Moving chats between buckets goes through `BucketsState` (`src/lib/state/buckets.svelte.ts`); its dialogs (the hold popover `HoldDialog`, "End this chat and archive it?", the archive-older confirmation) and the notice for skipped chats are hosted once by `BucketDialogs`, and hold dates come from `src/lib/format/hold.ts`. v1.3 usage: `UsageStore` (`src/lib/state/usage.svelte.ts`) mirrors `usage.get` / `usage.changed` for the strip's `UsageMeter`, the `UsageDialog` and a chat's limit notice; `ScheduledState` (`src/lib/state/scheduled.svelte.ts`) mirrors every scheduled send for the composer's "Schedule send…" menu and `ScheduleDialog`, the chat's `ScheduledSends` list above the composer and the `ScheduledBadge` clock on rows and tabs; times come from `src/lib/format/usage.ts`. Components read state through `useApp()` (`src/lib/state/context.ts`), so tests can pass their own wired state via Svelte context. shadcn-svelte components live in `src/lib/components/ui/` (added with `pnpm exec shadcn-svelte add …`).
- **Service restart** (`service_stop`, `ServiceBanner`, `ServiceDialogs`): an older service of the same protocol shows a thin "The Threadgarden service is an older version" bar, an incompatible one a blocking screen; **Restart service** confirms (listing the running agents), asks the service to shut down with all its work (`service.shutdown {stopAll: true}`, over the socket or, for another protocol, by `service_stop`), waits for its process to exit, then `service_connection` starts the app's version and the client reconnects. The tray's "Quit Threadgarden completely…" confirms the same way, shuts the service down and exits; "Quit Threadgarden (keep agents running)" just exits. On macOS a Dock click (`RunEvent::Reopen`) shows the hidden window.
- **Quick switcher, settings, attention** (`QuickSwitcher`, `SettingsDialog`, `src/lib/notifications.ts`, `src/lib/theme.ts`): Ctrl/Cmd+K searches titles, projects and full text (`search.quick` per keystroke, stale answers dropped) and hosts "New chat in…", "Stop all work" and "Settings" (and, in Active or a project, "Archive chats older than 30 days…"); archived matches come last, in their own group. Settings edits every service setting (idle minutes 0–1440, Claude Code path with a file picker, the Appearance section, start on login through the autostart plugin) and the API key (saved to the credential store, then `auth.setApiKey`; a stored key is sent after every `hello`). A chat that needs the user while it is not the active tab of a focused window posts a notification; focusing the window within 30 s afterwards selects "Needs you" and opens the chat if it is the only one waiting (the plugin reports no clicks, ruling R26). A hold that runs out posts "‹title› is back from hold" (same setting and focus rule; holds ending together are one "‹title› and N more" notification); holds that ended while no window was connected are announced on connect, once (the announced ids are kept in `uiState`). The tray badge follows the needs-you count; window focus/blur is sent as `ui.visibility`. The theme is `data-theme="light|dark"` on `<html>` (`system` follows the OS live); the appearance settings (`src/lib/appearance.ts`, tokens in `src/routes/themes.css`) are `data-accent`, `data-light-style`, `data-dark-style` and `data-ui-font` next to it, plus `--font-mono` for a custom code font, with a live preview in Settings (`AppearancePreview`). A copy in `localStorage` is applied by `app.html` before the first paint.
- **Analytics** (`src/lib/components/analytics/`, `src/lib/state/analytics.svelte.ts`, v1.3): `AnalyticsView` in the main pane, shown by `TabsState.showAnalytics` as a pseudo-tab beside the chat tabs (`analyticsOpen` / `analyticsShown`; no chat is active meanwhile). Plain SVG charts (`ColumnChart`, `BarList`, `Heatmap`) inside `ChartCard` (title, description, "Show data" with a `DataTable`); colors are CSS variables in `AnalyticsView` with separate light and dark steps.
- **Navigation guard** (`navigation.rs`): the webview only shows the app's own origin (`http://tauri.localhost` on Windows, `https://` with `useHttpsScheme`, `tauri://localhost` elsewhere, never with a port) and, under `tauri dev`, the dev server; links open in the system browser.
- **`src/lib/native.ts`** wraps every command and plugin (notification, dialog, clipboard, autostart). Outside Tauri it falls back to stubs and connects to the mock service given by `VITE_THREADGARDEN_MOCK_URL` (e.g. `ws://127.0.0.1:7357`) and `VITE_THREADGARDEN_MOCK_TOKEN`.

Scripts: `pnpm --filter desktop tauri dev` (builds the service first, then opens the app on the Vite dev server), `build` (static UI into `build/`), `test` (Vitest), `test:e2e` (Playwright, Chromium, `e2e/`: starts the mock service and a `vite preview` of a build in `build-e2e/` with the mock's address baked in; a smoke flow through a permission request, archiving and restoring a chat, and the §8 UI budgets — tab switch, history chat open, Ctrl+K keystroke, composer keystroke — timed inside the page from the input event to the DOM showing the result, multiplied by `THREADGARDEN_PERF_SLACK`), `typecheck`, `lint`. Rust: `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings` and `cargo test` in `src-tauri` (the UI must be built first). UI against the mock service: `THREADGARDEN_MOCK_PORT=7357 THREADGARDEN_MOCK_TOKEN=dev pnpm --filter @threadgarden/service mock`, then `VITE_THREADGARDEN_MOCK_URL=ws://127.0.0.1:7357 VITE_THREADGARDEN_MOCK_TOKEN=dev pnpm --filter desktop dev`.

Release bundles add `src-tauri/tauri.bundle.conf.json` (`tauri build --config src-tauri/tauri.bundle.conf.json`), which bundles the service and the Node sidecar; the sidecar binary (`src-tauri/binaries/threadgarden-node-<target triple>`, not committed) is fetched by `node scripts/fetch-node-sidecar.mjs --target <triple>` from the repo root (see the root README). The sidecar is installed next to the app executable (Windows install dir, macOS `Contents/MacOS`, Linux `/usr/bin` or the AppImage's `usr/bin`) and the service as the `service/service.mjs` resource (Windows install dir, macOS `Contents/Resources`, Linux `/usr/lib/Threadgarden`), which is where `service::release_target` looks (the exe's directory and Tauri's resource dir). Icons in `src-tauri/icons/` are generated from `app-icon.png` with `pnpm --filter desktop tauri icon app-icon.png`.
