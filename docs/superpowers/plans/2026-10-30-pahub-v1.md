# pahub v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build pahub v1 — a Tauri desktop app that replaces the Claude Code terminal UI for day-to-day work: projects, searchable history, live chats, a running-agents overview, and a full chat built on the Claude Agent SDK.

**Architecture:** A long-lived TypeScript **service** (Node.js, Agent SDK, `node:sqlite`) owns every Claude Code session, the history index, and external-session polling, and exposes a token-authenticated WebSocket on 127.0.0.1. A **Tauri 2 shell** (Rust) owns window, tray, notifications, keychain and launching the detached service. A **SvelteKit 5 static UI** talks to the service directly over the WebSocket. A shared **protocol** package types every message.

**Tech Stack:** pnpm workspace · TypeScript 5 (ESM) · Node 22 (`node:sqlite`, FTS5 trigram) · `@anthropic-ai/claude-agent-sdk@0.3.314` · `ws` · `zod` · Vitest · Tauri 2 (`@tauri-apps/cli@2.12.x`) with plugins notification, single-instance, autostart, dialog, clipboard-manager · Rust `keyring` · SvelteKit 3.1 + Svelte 5 (runes) + `@sveltejs/adapter-static` · Tailwind CSS 4 + shadcn-svelte · `marked` + DOMPurify + `shiki` (lazy) · `diff` · `fuzzysort` · Playwright · esbuild.

**Spec:** `docs/superpowers/specs/2026-10-30-pahub-v1-design.md` — read it before any task; section numbers below (§) refer to it.

## Global Constraints

- **Read-only toward Claude Code (§2 anti-goal 2, §5.1):** pahub code never writes, renames, moves, or deletes anything under the Claude config dir (`CLAUDE_CONFIG_DIR` or `~/.claude`). Never parse transcript `.jsonl` contents; never read `~/.claude/jobs/`. Never call `renameSession()` or `tagSession()`. File-system access under `~/.claude/projects` is limited to watching and `stat` (names, mtimes, sizes).
- **History only via the Agent SDK:** `listSessions()`, `getSessionInfo()`, `getSessionMessages()`, `forkSession()`.
- **Sessions started by pahub use:** `settingSources: ["user","project","local"]`, `systemPrompt: { type: "preset", preset: "claude_code" }`, `cwd` = project dir, `includePartialMessages: true`, `pathToClaudeCodeExecutable` = the installed `claude` (no bundled-binary fallback). User text is sent **without** `client_composed`, so `@path` mentions and `/commands` behave exactly as in the CLI.
- **Forward compatibility (§2 anti-goal 3):** every unknown SDK message type, content block, `claude agents` field or value maps to a generic `unknown` item/status rendered with raw JSON — never dropped, never a crash. All external inputs are parsed with lenient (`passthrough`) schemas.
- **Service network:** binds `127.0.0.1` only, random port, bearer token (32 random bytes, hex). `service.json` written atomically (temp + rename) with mode `0o600`.
- **Data dir:** `%APPDATA%\pahub` (Windows), `~/Library/Application Support/pahub` (macOS), `${XDG_DATA_HOME:-~/.local/share}/pahub` (Linux); overridable with env `PAHUB_DATA_DIR`.
- **Timings (§4.2–§4.4, §6.3):** idle reclaim 15 min (setting, 0 disables); service idle exit 30 min with no live sessions and no clients; external poll 2 s visible / 10 s hidden; transcript-recency warning 2 min; draft save debounce ≤ 300 ms.
- **Performance budgets (§8), enforced by tests where automatable:** tab switch ≤ 50 ms; history chat open ≤ 150 ms; Ctrl+K per keystroke ≤ 50 ms; full-text search ≤ 150 ms over 1,000 sessions; keystroke ≤ 16 ms; service idle RSS ≤ 150 MB.
- **Platforms:** Windows, macOS, Linux. No OS-specific code without the other two branches. CI on `windows-latest`, `macos-latest`, `ubuntu-22.04` must pass.
- **Branding:** the product is "pahub"; never call it "Claude Code" or mimic Claude Code's visuals (SDK branding guidelines). "Works with Claude Code" is fine.
- **Repo standards:** conventional commits with the `Co-Authored-By` trailer; LF line endings; no personal paths, tokens or machine details in committed files; every new package has a README section.
- **Svelte style:** Svelte 5 runes only (`$props`, `$state`, `$derived`, `$derived.by`); keyed `{#each}`; arrow-function declarations in TS.

## Review Focus

1. **Huge sessions** (≥ 2,000 messages, multi-MB tool outputs): opening, scrolling and streaming stay within budget — message list virtualised, tool outputs truncated in collapsed rows with "show all". → Task 14 test `renders 5,000 items with fewer than 120 DOM rows`; Task 6 test `indexes a 20 MB synthetic session without blocking > 50 ms`.
2. **Service restarted under live chats** (crash, reboot, version update): chats come back as "Interrupted — resume", nothing duplicated, no resume of a session running elsewhere. → Task 4 test `marks previously-live sessions interrupted on startup`; Task 8 tests for resume safety.
3. **UI reconnect mid-stream** (window reload, service briefly unreachable): no lost or duplicated chat items. → Task 4 test `replays events after seq without gaps or duplicates`; Task 12 test `resyncs after reconnect`.
4. **Paths with spaces, non-ASCII, Windows drive-letter casing, symlinks/junctions, git worktrees:** projects group correctly, `@` suggestions and `cwd` work. → Task 6 test `groups C:\\Repo and c:\\repo\\ as one project` and `groups worktrees under their repository`; Task 9 test `suggests files under a path containing spaces and non-ASCII`.
5. **Claude Code missing, too old, logged out, or refusing to start** (`cli_version_too_old`, `session_held_by_background`, auth errors): a clear explanation, never a hang or blank chat. → Task 5 test `maps every SDKStartupFailureReason to a user message`; Task 15 test `shows setup screen when claude is missing`.
