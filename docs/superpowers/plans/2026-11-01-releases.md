# Releases and self-update — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Pushing a `vX.Y.Z` tag publishes a GitHub Release with every installer, the headless package, signed update files and checksums, and the installed app updates itself on the owner's OK.

**Architecture:** A version script keeps every version in sync. A tag-triggered workflow reuses CI's checks, builds signed bundles with `tauri-apps/tauri-action` into a **draft** release, adds the headless package and checksums, validates the manifest and only then publishes. The desktop gains Tauri's updater and process plugins; a UI `UpdatesState` checks GitHub on a schedule and drives download → stop local service → install → relaunch, behind a confirmation when work is running.

**Tech Stack:** GitHub Actions, `tauri-apps/tauri-action@v0`, `tauri-plugin-updater` 2.x / `@tauri-apps/plugin-updater` ^2.14.1, `tauri-plugin-process` 2.x / `@tauri-apps/plugin-process` ^2.4.0, Svelte 5, vitest.

**Spec:** `docs/superpowers/specs/2026-11-01-releases-design.md`

## Global Constraints

- First release **0.3.0**; tags `vX.Y.Z`; the tag must equal `v` + the repo version or the release fails before building.
- Release assets: NSIS `setup.exe` + MSI (Windows x64), DMG (macOS arm64), deb + rpm + AppImage (Linux x64), updater bundles + `.sig`, `latest.json`, `threadgarden-headless-<version>-linux-x64.tar.gz` + `.sha256`, versionless `threadgarden-headless-linux-x64.tar.gz` + `.sha256`, `SHA256SUMS`.
- Updater endpoint: `https://github.com/JiriPlasek/ThreadGarden/releases/latest/download/latest.json`. Updates install only if signed with the project key.
- Never a half release: draft first, publish last, only when every job succeeded.
- Check shortly after start, then every **6 hours**; failures silent; dismissible notice, no modal, dismissed until the next version.
- Updating with running chats or pending scheduled sends on This PC asks first and names them; remote machines are unaffected.
- CI on every push stays **unsigned** and needs no secrets; signing/updater artifacts only in the release workflow (config overlay `tauri.release.conf.json`).
- deb/rpm installs get **Download** (release page), not self-update.
- Environment for agents (no links; pnpm `--config.verify-deps-before-run=false`; Rust via the toolchain's `cargo.exe`): see the agent-environment note the controller provides.

## Review Focus

1. **"Restart to update" while a chat is running on This PC** → a confirmation naming the chats; Cancel changes nothing. Test in Task 4.
2. **Offline or GitHub unreachable** → no error shown, next check at the interval, "Check for updates" says it couldn't reach GitHub. Test in Task 3.
3. **A download that fails signature verification or breaks mid-way** → error message, the local service still running, nothing installed. Test in Task 3 (the service is stopped only after a verified download).
4. **A platform job fails during a release** → no published release; the draft stays for inspection. Test in Task 5 (the `publish` job `needs` every build job; validated by the manifest check).
5. **Tag `v0.3.1` pushed on a commit whose version is 0.3.0** → the workflow fails in its first job, nothing built or drafted. Test in Task 5.

### Task 5: Release workflow

**Files:**
- Create: `.github/workflows/release.yml`, `scripts/release-sums.mjs`, `scripts/check-manifest.mjs` (+ tests next to Task 2's)
- Modify: `.github/workflows/ci.yml` (add `workflow_call:` to `on:` so release can reuse it unchanged)

**Interfaces:**
- `release.yml` triggers: `push: tags: ['v*']` and `workflow_dispatch` with input `dry_run` (boolean, default true) for branch rehearsals. `permissions: contents: write`. Jobs:
  1. `version` — fails unless `${GITHUB_REF_NAME}` = `v` + root `package.json` version (on `workflow_dispatch`: tag name `v<version>-dryrun-<short sha>`). **Review Focus 5.**
  2. `ci` — `uses: ./.github/workflows/ci.yml` (all existing checks, e2e included).
  3. `bundle` — `needs: [version, ci]`; matrix as CI's bundle job; fetch the Node sidecar; `tauri-apps/tauri-action@v0` with `projectPath: apps/desktop`, `args: --config src-tauri/tauri.bundle.conf.json --config src-tauri/tauri.release.conf.json`, `tagName`, `releaseName: Threadgarden v__VERSION__`, `releaseDraft: true`, `generateReleaseNotes: true`, `includeUpdaterJson: true`; env `TAURI_SIGNING_PRIVATE_KEY`, `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`, `GITHUB_TOKEN`.
  4. `headless` — `needs: [version, ci]`; `pnpm build:headless`; upload to the draft (`gh release upload`) the versioned tarball + `.sha256` and versionless copies `threadgarden-headless-linux-x64.tar.gz` + `.sha256` (the `.sha256` of the copy names the copy).
  5. `publish` — `needs: [bundle, headless]` (so any failure stops here: **Review Focus 4**); downloads all draft assets; `node scripts/check-manifest.mjs latest.json <version>` (fails unless `version` matches and `platforms` has `windows-x86_64`, `darwin-aarch64`, `linux-x86_64`, each with a `signature` and a `url` that names an asset present in the draft); `node scripts/release-sums.mjs <dir>` writes `SHA256SUMS` (all assets except itself, `sha256sum` format) and uploads it; then `gh release edit <tag> --draft=false --latest` — **only when not `dry_run`**; on a dry run it prints the asset list and deletes the draft and its tag.
- `check-manifest.mjs` exports `checkManifest(manifest: unknown, version: string, assets: string[]): string[]` (problems; empty = ok).
- `release-sums.mjs` exports `sumsFor(dir: string): Promise<string>`.

- [ ] **Step 1: Failing tests** for `checkManifest` (ok case; wrong version; a missing platform; a url naming an absent asset; a missing signature) and `sumsFor` (two files → two lines `<hex>  <name>`, sorted, excluding `SHA256SUMS`).
- [ ] **Step 2: Run** → FAIL. **Step 3: Implement** scripts and workflows; `actionlint` if available, else careful review.
- [ ] **Step 4: Rehearse on the branch** (controller-run, after Task 1's secrets exist): `gh workflow run release.yml --ref feat/releases -f dry_run=true` → every job green, the dry-run log lists every asset of Global Constraints, the draft is deleted afterwards. Fix and re-run until green.
