# pahub v1.1 — Activity panel, "Your turn", project order, autoscroll

**Date:** 2026-10-30
**Status:** Approved by owner (in conversation) for implementation
**Builds on:** [v1 design](2026-10-30-pahub-v1-design.md). Its anti-goals still outrank everything here: never slow, never damage Claude Code's data, never fall behind Claude Code, never crash or lose work.

## 1. Why

Owner feedback after using v1 daily:

1. "On the right of the conversation I'd like a dashboard of the agents running in the thread."
2. "Projects on the left should be sorted by recent" — pinned projects stay on top, then the rest by most recent activity.
3. "The chat should scroll to the latest message when I send one."
4. "Some visualisation of the running processes of the thread — for example when it runs a dev server."
5. "When a chat ends its turn with a question to me, I expect it under Needs you — or some other way to be told that a thread finished."

## 2. Activity panel (items 1 and 4)

A collapsible panel on the right side of the chat view, titled **Activity**, with two sections. It is hidden automatically when the chat has never had any tasks, and can be toggled (state remembered per window via `uiState`).

**Source of truth:** the Agent SDK already streams task lifecycle messages for each session: `system/task_started` (task_id, tool_use_id, description, subagent_type, task_type, is_backgrounded, parent_task_id), `system/task_progress` (usage: total_tokens, tool_uses, duration_ms; last_tool_name; summary), `system/task_updated` (patch.status: pending|running|completed|failed|killed|paused; end_time; error; is_backgrounded), `system/task_notification` (status completed|failed|stopped; summary; output_file) and `system/background_tasks_changed` (the current list). The SDK's `Query.stopTask(taskId)` stops a task and emits a `stopped` notification. v1 classified these as non-visual; v1.1 folds them into per-session task state instead of dropping them.

- **Agents:** subagents and background agents (task types for agents, and any task with a `subagent_type`). Each row: description, subagent type, status icon, elapsed time (live), tool uses and tokens, latest tool or summary. Clicking a row scrolls the chat to the tool call that started it (`tool_use_id`), when it is in the loaded items.
- **Processes:** background shell tasks (shell task types, e.g. a dev server or watcher started with `run_in_background`) and monitors. Each row: description/command, status, running time, and a **Stop** button (confirmation) that calls `stopTask`. Finished processes stay listed (dimmed) with their final status until the chat's process ends.
- Unknown task types are listed under Processes with their raw type shown (forward compatibility).
- **Badge:** chat tabs and chat-list rows show a small "N running" activity badge when the chat has running background tasks.
- **Not in v1.1:** live output of a running process. The SDK stream carries no incremental output for background shells; the panel shows status, command and duration, and the summary once the task ends.
- Tasks exist only for chats pahub runs (live sessions). History-only and external chats show no Activity panel content ("Activity is available for chats running in pahub").

## 3. "Your turn" — knowing a chat finished (item 5)

A chat pahub runs that **finishes a turn while you are not looking at it** becomes **unread**:

- "Not looking" = the chat is not the active tab of a focused pahub window at the moment the turn's `result` arrives.
- Unread chats appear in the **◐ Needs you** folder below the chats that wait on a permission, question or plan, marked with a distinct **"Your turn"** indicator (blue dot) and a preview of the last assistant text.
- The Needs you badge counts both kinds; the tray badge too.
- A desktop notification "‹title› finished — your turn" is posted when the setting **Notify when a chat finishes** is on (default on); it reuses the R26 focus behaviour (focusing the window soon after opens the chat if it is the only one).
- Opening the chat (active tab in a focused window) marks it seen. Sending a message, or the chat starting a new turn, also clears it.
- Seen/unread state is pahub's own (stored in `pahub.db`, never in Claude Code's data) and survives restarts.

## 4. Project order (item 2)

- Order stays: **pinned projects first (by most recent activity among themselves), then all others by most recent activity.** Activity includes live chats, so a project moves up as soon as a chat in it is active, without waiting for re-indexing.
- Projects whose folder no longer exists on disk are moved into a collapsed **Missing folders** group at the bottom of the project list (checked with a cheap existence test, cached and refreshed periodically, never touching Claude Code's data).

## 5. Autoscroll on send (item 3)

Sending a message (Enter, the Send button, a queued send, or answering a question/permission that resumes work) scrolls the chat to the bottom and re-enables following new output, even if the user had scrolled up. Scrolling up afterwards pauses following again, as today.

## 6. Out of scope

Live process output; stopping tasks of external (non-pahub) sessions; agent-team dashboards.
